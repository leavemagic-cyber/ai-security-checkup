## 主文

用 AI 寫程式、接 MCP、跑自架工作流的人，今天值得花幾分鐘檢查更新。

Node.js 10/21 公布 10 項漏洞，其中包含可能讓攻擊者執行程式的問題；另有漏洞會讓連線時「確認對方身分」的檢查出錯。不是所有 AI 使用者都中招，要看工具版本和使用條件。

這批 Node 至少更新到：
22.x → 22.23.4
24.x → 24.22.1
26.x → 26.12.1

最容易漏掉的是：系統 Node 更新了，桌面 App、MCP、Docker 裡那一份可能還是舊的。

我整理了免費開源的檢查工具與白話更新指南，也補上近期 Claude、MCP、n8n 官方安全公告。工具離線、不讀密鑰、不自動改設定；每項附官方來源。

https://github.com/leavemagic-cyber/ai-security-checkup

只用網頁版 AI 的人，先維護瀏覽器和系統，不必因此另外安裝 Node。

AI 協助整理，已核對官方公告。資料日期：2026/10/23。

## 接續 1：還有哪些情況

另外幾個近期官方公告，也值得對號入座：

• Windows Claude Desktop：惡意專案若藏了假 Git，舊版 App 開啟資料夾時可能就執行它。桌面版修補門檻 1.8089.0。
• macOS Claude Desktop：Cowork 資料夾裡的惡意檔案，被打開時可能在主機執行。修補門檻 1.15962.0。
• Claude Code：特定條件下，外掛即使鎖定版本仍可能裝到攻擊者程式；CLI 修補門檻 2.1.179。
• 部分 HTTP／OAuth MCP 客戶端可能洩露登入憑證；某些多人 HTTP MCP 服務可能把甲的回覆送給乙。升級之外，還可能要處理舊憑證與修改連線隔離。
• n8n：有建立、執行工作流權限的人，可能越權操作其他專案的資料表；2.43／2.44 分支修補門檻分別為 2.43.5／2.44.1。

每個都有條件，不能直接推論已遭入侵。完整來源與步驟放在 Repo 的 docs/ADVISORIES.md。

## 接續 2：怎麼做才算完成

快速處理順序：

1. 看自己用的是網頁、桌面 App、CLI，還是自架服務。
2. 查實際版本和執行路徑；Node 可用 node --version 與 node -p "process.execPath"。
3. 用原安裝方式更新，並檢查 App 內建副本、MCP 相依套件、容器與 CI。
4. 保存工作，安排相關程式重新啟動，再查版本與功能。

若受影響的 MCP 可能連過惡意伺服器，只更新不能把已外洩的憑證收回來；依公告撤銷權杖、輪替相關密鑰。

Repo 工具不用 npm install，不連網，也不會替你亂升級。它只查列出的公告；看到通過，不代表整台電腦沒有其他漏洞。最低修補版也有日期，以後仍要看官方更新。
