# AI Security Checkup｜不懂電腦，也能讓 AI 帶你安全更新

[English](README.md)

**看到資安新聞，卻不知道自己要不要處理？把下面這段話貼給 AI，讓它先查、問你，再幫你更新。**

某些漏洞可能讓人偷走登入權限、讀取資料，甚至在你的電腦執行程式。是否影響你，要看你使用的軟體與版本；不用先學會看漏洞代號。

**你每天用的 Chrome／Firefox、Windows、iPhone／iPad／Mac、Android 都有列入[白話提醒](docs/PERSONAL-ALERTS.zh-TW.md)。** 用 ChatGPT、Gemini、Claude 網頁聊天，先檢查瀏覽器與系統；裝了 AI 桌面軟體或外掛，再查實際使用的 App 與內建元件。讓 AI 判斷你需要哪一項處理。

## 只要三步

1. **複製下面的話，貼給你使用的 AI。**
2. **讓 AI 查清楚，白話告訴你哪些需要處理。**
3. **確認後回答「好，幫我更新」。**讓 AI 協助完成，再確認真的修好了。

不用下載這個 Repo，也不用先安裝 Node 或學打指令。能操作電腦的 AI 可以協助執行；一般聊天 AI 若無法讀取或操作裝置，就應該明說，改用一次點一個畫面的方式帶你做。手機也能使用同一段話，取得適合該裝置的更新指引。**Prompt 本身不會替 AI 增加它原本沒有的操作能力。**

## 複製這段，貼給 AI

點右上角的複製按鈕即可。也有[單獨的提示詞檔案](prompts/QUICK-UPDATE.zh-TW.md)。

````
請當我的電腦安全小幫手。我沒有資訊背景，請直接幫我查清楚，用白話帶我完成修補。

先檢查，不要立即更新。請先確認你能不能讀取或操作我的裝置：能取得的資料請自己查，不要叫我開終端機、找版本號或看程式碼；若你沒有這些能力，要明說，改成一次教我點一個畫面，不要假裝已經掃描。只有必要時才問我使用哪種裝置。

請按照這個流程做：

1. 查我實際使用的系統、瀏覽器、常用軟體及 AI 工具。優先查最近七天官方公布、會影響個人使用者的安全問題；較早公布但仍未修補的重大問題也要留意。只查我有使用的產品，不要為了檢查而安裝新工具或掃描私人文件。找不到某個程式，不等於已確認沒有安裝。

2. 對照最新官方公告與真正的安裝版本、來源和使用條件，判斷是否需要更新。用「哪個軟體、可能發生什麼事、現在要不要處理」告訴我，最多先列最重要的五項。附官方來源，但不要用漏洞代號或專業術語代替解釋。分清楚已確認受影響、只是建議更新、還無法確認。

3. 準備好可執行的更新方式後，問我：「要幫你更新這幾項嗎？」同時說清楚會更新哪些軟體、是否收費、是否需要關閉程式或重新啟動，以及未儲存的內容可能受影響。等我明確回答「好，幫我更新」才開始，不要把這段提示詞當作更新同意。

4. 我同意後，能代做的就直接完成。沿用原本的官方更新、官方商店或既有套件管理方式，只更新剛確認的項目；不要安裝來路不明的修復工具、關閉安全保護、刪除我的資料或亂升所有軟體。需要改用不同主版本、付費或出現額外影響時，再用白話說明並詢問。登入、系統權限或工具規則要求我親自處理的地方，再告訴我按哪裡；不要索取或顯示我的密碼、金鑰或驗證碼。

5. 更新後重新查實際生效的版本與狀態，確認軟體能正常使用。注意軟體可能藏著自己的舊元件；不能因為外面那份更新了就說全部修好。若公告還要求重新登入、撤銷可能外洩的登入權限或其他後續處理，也要用白話帶我做。沒有完成的項目要明說原因及下一個最簡單的動作，不能只看到下載完成就說修好了。

最後只要簡短告訴我：「已處理哪些、還剩哪一步、我現在能不能繼續正常使用。」不要公開或上傳我的電腦資料。
````

## 最近有哪些值得處理？

[看個人使用者的白話提醒與最簡單處理方式](docs/PERSONAL-ALERTS.zh-TW.md)。每項附日期與官方來源；沒有用到的軟體不用跟著安裝或修補。

最近的問題不只在 AI 工具裡，瀏覽器、作業系統和常用軟體也要看。提示詞會要求 AI 查當下的官方資訊，不把這份 Repo 的舊版本表當成永遠最新的答案。

**有幫你省下時間、順利完成更新，請幫這個 Repo 按個 ⭐，也歡迎把連結轉給需要的人。** 免費使用，不需要先按星或交出個人資料。

## 一分鐘開始檢查

按 GitHub 的 **Code → Download ZIP**，解壓縮後在該資料夾開啟終端機。也可以用 Git：

```sh
git clone https://github.com/leavemagic-cyber/ai-security-checkup.git
cd ai-security-checkup
node check.mjs
```

不需要 `npm install`、帳號、API 金鑰或管理員權限。執行前可以直接閱讀短小的原始碼。工具只使用 Node 內建功能，不連網、不執行其他程式、不改設定。用舊版 Node 執行檢查，不會順便修好它。如果沒有安裝 Node，而且只用網頁版 AI，直接看手動指南，不必為了檢查而安裝 Node。

Node.js 2026-10-21 這批公告的修補門檻：

| 原本的主版本 | 這批漏洞至少更新到 |
| --- | --- |
| 22.x | 22.23.4 |
| 24.x | 24.22.1 |
| 26.x | 26.12.1 |

這是有日期的最低門檻，之後仍可能需要新修補。請選符合現有主版本及相容性需求的最新受支援修補版。未列出的分支與預覽版會顯示 `REVIEW`，不會因為版本數字較大就被判定安全。[Node 官方公告](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)。

## 加查專案或指定版本

```sh
# 讀取指定專案的 npm package-lock.json，包括巢狀相依套件
node check.mjs --project /path/to/your/project

# 比對手動提供的版本；不代表已檢查正在執行的 App
node check.mjs --component @modelcontextprotocol/client@2.1.0
node check.mjs --node-version 24.21.0

# JSON 結果可能包含私人本機路徑
node check.mjs --json
```

Windows 專案路徑可寫成 `--project "C:\your-project"`。要另外查看目前名稱為 `node` 的執行中程序，其檔案版本與路徑，可以選擇執行：

```powershell
powershell -NoProfile -File .\scripts\Inspect-RunningNode.ps1
```

如果公司政策擋住腳本，請照手動盤點步驟處理，不要關閉政策。這個 PowerShell 輔助工具只讀取檔案版本資訊與路徑，不會停止或更新程序。磁碟上的版本資訊，也不能證明舊程序已經載入更新後的檔案。

## 結果怎麼看

| 狀態 | 意思 |
| --- | --- |
| `AFFECTED_VERSION` | 版本落在已列出的受影響範圍；核對觸發條件並處理。 |
| `MEETS_BASELINE` | 這份 Node 的版本達到本次公告門檻。 |
| `NO_VERSION_MATCH` | 此套件沒有命中這條公告的版本範圍；其他漏洞未檢查。 |
| `MANUAL_CHECK` | 只看版本不能確認舊憑證已處理，或連線隔離已修改。 |
| `REVIEW`／`INCOMPLETE` | 版本或分支不明、格式不支援、讀取失敗，不能判定通過。 |

結束碼：**0**＝沒有列出的版本警示，**1**＝有受影響版本，**2**＝資料不足或需要人工確認。若同時有受影響版本與人工確認項目，以 2 為準。沒有套件命中，不代表專案或整台電腦安全。

## 檢查範圍與限制

- 比對執行此工具的 Node、明確提供的版本，以及選擇讀取的一份 npm v1／v2／v3 lockfile；資料來自 `advisories.json`。
- 套件精選範圍：Claude Code 外掛版本釘選、MCP TypeScript SDK 的 OAuth／任務／權杖問題、MCP 2.x HTTP 伺服器共用實例、n8n Data Table 專案隔離。每條都有條件與官方來源。
- PATH 中其他 Node 路徑只列出，**不會執行或檢查其版本**。版本管理器裡其他副本、未啟動 App、Electron、App 內建 runtime、其他使用者、Docker、WSL、CI 與遠端主機，都不會自動完整盤點，請逐一照指南檢查。
- Lockfile 記錄預期解析的版本，不能證明安裝、建置或執行中的版本。工具不支援 pnpm、Yarn、Bun 與 Python lockfile；要求讀取的 npm lockfile 缺少或損壞會回報資料不足。
- 工具不讀憑證、MCP 設定或 OAuth 儲存內容，不攻擊目標、不偵測入侵、不安裝修補、不上傳報告。結果可能帶有本機路徑，公開前請遮除。
- 更新系統 Node，不保證 App 內建副本也更新。請透過廠商支援的更新方式處理，安排重新啟動後再查。更新也不會撤銷已被偷走的權杖；如有可能暴露，依公告處理。
- 這是**有日期的資料快照**，沒有背景監控或自動更新漏洞庫。之後使用時，先查目前官方公告。
